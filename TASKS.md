# Практика 2. Полигон конфликтов

Шесть задач. Каждая выполняется **в ветке `main`** этого репозитория:
вы сливаете в неё ветку задачи и разбираетесь с тем, что получится.

## Правила

1. Задачи выполняются **по порядку**: каждая следующая опирается
   на состояние после предыдущей.
2. Ничего не удаляйте и не клонируйте заново. Любое состояние обратимо —
   разобраться в нём и есть задание.
3. Если совсем запутались: `git merge --abort`, `git rebase --abort`,
   `git reflog`.
4. После каждой задачи записывайте ответ в `ANSWERS.md` (создайте его сами).

## Задача 1. Конфликт в одной строке

```
git merge task-01-precision
```

Разрешите конфликт: оставьте значение с 14 знаками.

**В ANSWERS.md:** приведите содержимое файла в момент конфликта
(вместе с маркерами) и объясните, что означает каждая из трёх строк-маркеров.

## Задача 2. Конфликт в соседних строках

```
git merge task-02-settings
```

Конфликт возник, хотя изменены **разные** строки словаря.

Разрешите так, чтобы в итоге присутствовали все три ключа:
`verbose: True`, `log_level`, `timeout`.

**В ANSWERS.md:** почему Git не справился сам, если строки разные?

## Задача 3. Изменён против удалён

```
git merge task-03-legacy
```

Git сообщит о конфликте особого рода.

Примите решение: оставить файл или удалить. Любой вариант засчитывается,
если он осознанный.

**В ANSWERS.md:** приведите текст сообщения Git, объясните, в чём
отличие этого конфликта от задач 1–2, и обоснуйте своё решение.

## Задача 4. merge против rebase

Здесь конфликта не будет. Задача — увидеть разницу в графе.

```
git merge task-04-merge
git log --graph --oneline --all
```

Сохраните вывод. Затем **отмените это слияние**:

```
git reset --hard HEAD~1
```

и проделайте то же самое перебазированием:

```
git switch task-04-rebase
git rebase main
git switch main
git merge task-04-rebase
git log --graph --oneline --all
```

**В ANSWERS.md:** оба вывода `git log --graph` и объяснение,
чем отличаются получившиеся истории. Сколько коммитов в каждом случае?
Совпадают ли хеши коммитов из ветки?

## Задача 5. Потерянный коммит

```
git switch task-05-lost
git log --oneline
```

Запомните, что видите. Теперь сломайте:

```
git reset --hard HEAD~2
```

Два коммита, включая тот, что помечен как важный, пропали из ветки.

**Верните их**, не пользуясь `git reflog` для первой попытки —
сначала попробуйте найти хеш другим способом и опишите, получилось ли.
Затем восстановите через `reflog`.

**В ANSWERS.md:** вывод `git reflog`, команда, которой вы восстановились,
и ответ на вопрос: куда делись коммиты в промежутке между `reset`
и восстановлением? Они были удалены?

После восстановления слейте ветку в `main`.

## Задача 6. Слияние, которое надо отменить

```
git switch main
git merge task-06-bad
```

Слияние пройдёт без конфликта. Но внесённое изменение содержит ошибку —
найдите её (посмотрите, что изменилось в `src/stats.py`).

Отмените это слияние **так, чтобы отмена осталась в истории**
(не переписывая её).

**В ANSWERS.md:** какой командой вы это сделали и почему именно ею,
а не `reset`. Что означает флаг, который вам понадобился?

## Что сдаётся

- файл `ANSWERS.md` с ответами на все шесть задач;
- итоговое состояние `main` после всех задач;
- вывод `git log --graph --oneline --all` на момент сдачи
  (последним блоком в `ANSWERS.md`).

История не должна быть переписана «начисто»: мне интересен путь,
а не аккуратный результат.
